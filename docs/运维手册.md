# gzh-platform 运维手册

本文记录日常运行、数据同步、排障和发布前检查步骤。

## 本地启动

后端：

```powershell
cd backend
.\.venv\Scripts\activate
python app.py
```

前端：

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 3001
```

浏览器访问：

```text
http://127.0.0.1:3001/settings
```

## 部署环境检查

首次启动后先打开设置页，检查：

- `.env` 是否存在
- 文章目录是否存在
- 微信公众号 AppID/AppSecret 是否填写
- 本机公网 IP 是否加入公众号后台白名单
- AI Provider、Base URL、API Key、Model 是否可用
- Node.js、Wenyan 依赖、Git 是否可用

## 手动同步数据看板

在前端点击：

```text
数据看板 -> 更新数据
```

同步结果会写入：

- `article_stats`: 每篇文章最新统计
- `sync_status`: 最近一次同步状态

看板页面会每 60 秒读取 `GET /api/analytics/sync-status`。

## 定时同步数据看板

Windows 任务计划程序建议执行：

```text
backend\scripts\run_wechat_stats_sync.bat
```

建议频率：

- 普通使用：每天 09:00 和 18:00
- 发文频繁：每 2-4 小时

日志文件：

```text
backend\scripts\wechat_stats_sync.log
```

该日志只属于本机，不提交 GitHub。

## 命令行同步

API 来源：

```powershell
cd backend
python scripts\sync_wechat_stats.py --source api
```

HTML dry-run：

```powershell
cd backend
python scripts\sync_wechat_stats.py --source html --html-path scripts\publish_records.html --dry-run
```

JSON dry-run：

```powershell
cd backend
python scripts\sync_wechat_stats.py --source json --json-path scraped_articles.json --dry-run
```

先看输出里的：

- `matched`
- `unmatched`
- `ambiguous`

确认没有明显错配后再去掉 `--dry-run`。

## 常见故障

### 前端 502

后端没有启动，或 5001 端口不可达。

处理：

```powershell
cd backend
python app.py
```

### 微信 API 返回 IP 白名单错误

在微信公众号后台添加当前机器公网 IP。

### 数据看板全是 0

按顺序检查：

1. 设置页“测试微信公众号连接”是否通过
2. 是否点击过“更新数据”
3. `sync_status` 是否显示失败
4. 同步结果中是否有 `unmatched` 或 `ambiguous`
5. 当前配置的公众号是否真的发布过这些文章

### 同步状态不刷新

检查接口：

```powershell
Invoke-RestMethod http://127.0.0.1:5001/api/analytics/sync-status
```

如果 404，说明后端是旧进程，需要重启 Flask。

## 发布前检查

```powershell
cd backend
python -m unittest discover -s tests

cd ..\frontend
npx tsc -b
npm run build
```

Windows 上 `npm run build` 如果在受限沙箱中出现 `EPERM`，在普通终端重新执行即可。
