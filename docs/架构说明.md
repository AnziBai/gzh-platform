# gzh-platform 架构说明

本文面向接手开发和维护的同事，说明系统模块、数据流、数据模型和关键 API。

## 总体结构

```text
React + Vite + Ant Design 前端
  -> /api/*
Flask + SQLAlchemy + SQLite 后端
  -> OpenAI-compatible API 或 Claude CLI
  -> 微信公众号 API
  -> Wenyan 排版发布脚本
  -> 本地文章、素材、知识库文件
```

## 业务闭环

```text
热点源/文章/搜索结果
        |
        v
统一 HotItem / SourceItem
        |
        v
AI 摘要 + 分类 + 去重
        |
        v
素材候选池 material_candidates
        |
        v
人工确认 approve/reject
        |
        v
正式素材库 benchmarks + Markdown 文件
        |
        +--> 文章工坊推荐事实素材、爆款参考、知识库片段
        |
        +--> 发布前改写参考
```

知识库文件单独进入 `knowledge_files` 和 `knowledge_chunks`，不混入爆款素材库。文章生成时可以同时使用：

- 一个主题或热点简报。
- 多个事实素材。
- 一个爆款参考。
- 多个知识库片段。

## 前端模块

| 页面 | 职责 |
| --- | --- |
| 选题库 | 抓取热点、筛选、生成创作简报、从热点生成文章 |
| 素材库 | 审核 AI 候选、管理正式素材、上传知识库 |
| 文章工坊 | 输入主题、推荐素材和知识片段、生成文章 |
| 发布中心 | 发布前改写、发布到公众号草稿箱 |
| 数据看板 | 公众号数据同步和指标展示 |
| 设置 | 配置向导、模型预设、密钥保存、部署诊断 |

移动端由 `frontend/src/components/Layout.tsx` 切换到顶部导航，文章工坊会纵向堆叠，避免固定侧栏挤压内容。

## 数据模型

| 表 | 用途 |
| --- | --- |
| `articles` | 本地文章元数据、状态、media_id、关联选题和素材 |
| `article_stats` | 微信公众号阅读、分享、点赞、推荐、评论、划线等统计 |
| `benchmarks` | 正式素材库，含 `material_type`、来源、去重 hash 和候选来源 |
| `material_candidates` | 自动收集候选池，含分类建议、置信度、来源 URL 和审核状态 |
| `knowledge_files` | 用户上传知识库文件，记录解析状态和分块数量 |
| `knowledge_chunks` | 知识库分块，保存正文、关键词和 content hash |
| `topics` | 热点选题，保存状态、创作简报、素材、知识片段和生成文章关联 |
| `tasks` | 后台任务进度、日志、结果、错误 |
| `sync_status` | 数据看板最后一次同步状态 |

SQLite 不使用 Alembic。`init_db()` 会幂等创建新表，并为旧库补齐新增列。

## 关键状态

Topic 状态：

- `new`：新热点。
- `selected`：已选为选题。
- `used`：已生成文章。
- `dismissed`：已忽略。

MaterialCandidate 状态：

- `candidate`：待确认。
- `approved`：已入正式素材库。
- `rejected`：已忽略。
- `failed`：分类或收集失败。

Benchmark 类型：

- `reference_article`：爆款范文/仿写参考。
- `fact_material`：事实资料/案例/数据。

## 关键 API

所有接口默认前缀为 `/api`。

| API | 用途 |
| --- | --- |
| `POST /topics/scrape` | 抓取热点，支持 `source_group`、`mode`、`category`、`since_hours`、`keyword` |
| `POST /topics/<id>/brief` | 生成并保存热点创作简报 |
| `POST /topics/<id>/generate` | 基于热点简报生成文章 |
| `POST /materials/collect` | 从文章、热点或搜索收集素材候选 |
| `GET /materials/candidates` | 查看素材候选 |
| `POST /materials/candidates/<id>/approve` | 候选确认入库 |
| `POST /materials/candidates/<id>/reject` | 候选拒绝 |
| `POST /knowledge/files` | 上传 Markdown/TXT/PDF 知识库文件 |
| `POST /knowledge/recommend` | 为主题推荐知识片段、事实素材和爆款参考 |
| `POST /articles/generate` | 手动主题生成文章 |
| `POST /articles/<slug>/rewrite-for-publish` | 发布前改写，生成新草稿 |
| `POST /articles/<slug>/publish` | 发布到公众号草稿箱 |
| `GET /settings/model-presets` | 模型预设 |
| `POST /settings/bootstrap` | 创建本地目录并写入 `.env` |

## 可靠性设计

- 自动收集先进入候选池，人工确认后才进入正式素材库。
- 素材入库使用 `source_hash + material_type` 去重。
- 外部热点/API 请求要有超时和清晰错误，不阻塞其他来源。
- 搜索结果没有来源 URL 时不能作为正式事实入库。
- 文章生成和发布前改写会规范化 AI 输出，补齐 Markdown frontmatter。
- 发布前改写不覆盖原文，只生成新草稿。
- 设置页诊断把 PDF parser 缺失标成非阻塞：Markdown/TXT 知识库仍可用。
