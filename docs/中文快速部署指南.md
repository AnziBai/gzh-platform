# gzh-platform 中文快速部署指南

这份文档给第一次接手项目的同事使用。目标是：从 GitHub 拉代码，在自己的电脑上完成配置，并启动公众号内容运营平台。

如果你只是想最快跑起来，优先使用项目根目录的 `.\start-dev.ps1`。它会自动创建 Python 虚拟环境、安装后端依赖、安装前端依赖，并启动前后端服务。打开设置页后，再用“首次部署向导”和“开箱即用进度”补齐目录、AI 和公众号配置。

如果你希望了解脚本背后的目录和 `.env` 示例，可以再看：[自动初始化配置示例](自动初始化配置示例.md)。

## 1. 项目用途

`gzh-platform` 是一个公众号内容运营平台，包含：

- 文章生成与审查
- 发布中心
- 选题库
- 数据看板
- 微信公众号阅读、分享、点赞、推荐、划线等数据同步

## 2. 环境要求

建议使用 Windows 电脑。需要提前安装：

- Git
- Python 3.10+
- Node.js 20+
- npm

可在终端检查：

```powershell
git --version
python --version
node --version
npm --version
```

## 3. 拉取代码

```powershell
cd C:\Users\你的用户名\Documents
git clone https://github.com/AnziBai/gzh-platform.git
cd gzh-platform
```

## 4. 推荐：一键启动

```powershell
.\start-dev.ps1
```

第一次运行时脚本会做这些事：

- 创建 `backend\.venv`
- 安装 `backend\requirements.txt`
- 安装 `frontend\package-lock.json` 对应的前端依赖
- 分别启动后端和前端窗口

启动后打开：

```text
http://127.0.0.1:3001/settings
```

进入设置页后先点击“首次部署向导”，再看“开箱即用进度”。一般按这个顺序处理：

1. 准备本地工作区
2. 配置 AI 写作
3. 连接微信公众号
4. 启用排版发布

如果你已经手动安装好依赖，只想启动服务：

```powershell
.\start-dev.ps1 -SkipInstall
```

## 5. 手动安装后端依赖

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

如果公司网络访问 Python 源较慢，可以先配置国内镜像源。

## 6. 手动安装前端依赖

打开新的终端：

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform\frontend
npm install
```

## 7. 创建后端配置文件

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform\backend
copy .env.example .env
```

然后编辑 `backend\.env`。

## 8. 必填配置

### 8.1 本地文章目录

如果你没有单独的文章仓库，可以先创建一个本地目录：

```powershell
mkdir C:\gzh-content\articles\published
```

然后在 `.env` 中填写：

```env
GZHPUBLISHER_ROOT=C:/gzh-content
ARTICLES_DIR=C:/gzh-content/articles/published
BENCHMARKS_DIR=C:/gzh-content/benchmarks
```

### 8.2 微信公众号配置

在微信公众号后台获取：

```env
WECHAT_APP_ID=你的 AppID
WECHAT_APP_SECRET=你的 AppSecret
```

注意：必须把本机公网 IP 加入微信公众号后台的 IP 白名单，否则看板无法拉取真实数据。

### 8.3 AI 写作模型配置

支持两种方式。

方式 A：Claude CLI

```env
AI_PROVIDER=claude_cli
CLAUDE_BIN=C:/Users/你的用户名/AppData/Roaming/npm/claude.cmd
```

方式 B：OpenAI-compatible API

适用于 DeepSeek、OpenAI、智谱、通义等兼容接口：

```env
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=你的 API Key
AI_MODEL=deepseek-chat
```

如果不确定用哪个，建议先用 OpenAI-compatible API，迁移到其他电脑更简单。

## 9. 手动启动项目

### 9.1 启动后端

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform\backend
.\.venv\Scripts\activate
python app.py
```

后端默认地址：

```text
http://127.0.0.1:5001
```

### 9.2 启动前端

打开新的终端：

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform\frontend
npm run dev -- --host 127.0.0.1 --port 3001
```

前端默认地址：

```text
http://127.0.0.1:3001
```

## 9. 首次打开后要做什么

浏览器打开：

```text
http://127.0.0.1:3001/settings
```

先看“部署环境检查”，按页面提示处理缺失项。

然后点击：

- 测试微信公众号连接
- 测试 AI 连接

两个测试都通过后，再去数据看板或发布中心使用。

## 10. 数据看板同步

手动同步：

```text
数据看板 -> 更新数据
```

系统会从微信公众号 API 拉取真实数据，并写入本地 SQLite 数据库。

看板会显示最近同步状态：

- 最近同步时间
- 更新了多少文章
- 有多少标题未匹配
- 有多少标题存在歧义并被跳过

歧义标题不会写入数据库，避免把某篇文章的数据写到另一篇文章上。

## 11. 定时同步数据

项目内置了 Windows 定时任务可用的脚本：

```text
backend\scripts\run_wechat_stats_sync.bat
```

可以在 Windows “任务计划程序”中新建任务，定时执行这个脚本。

建议频率：

- 普通使用：每天 09:00 和 18:00 各同步一次
- 发文频繁：每 2-4 小时同步一次

同步日志会写到：

```text
backend\scripts\wechat_stats_sync.log
```

这个日志不会提交到 GitHub。

## 12. 常见问题

### 12.1 页面显示 502

通常是后端没有启动，或 5001 端口被防火墙/其他程序拦截。

处理：

```powershell
cd backend
python app.py
```

然后刷新前端页面。

### 12.2 微信公众号连接失败

常见原因：

- AppID 或 AppSecret 填错
- 本机公网 IP 没有加入公众号后台白名单
- 当前公众号没有对应 API 权限
- 公司网络或代理阻断了 `api.weixin.qq.com`

### 12.3 AI 连接失败

检查：

- `AI_PROVIDER` 是否正确
- `AI_BASE_URL` 是否以 `/v1` 结尾
- `AI_API_KEY` 是否有效
- `AI_MODEL` 是否是该服务商支持的模型名
- 如果用 Claude CLI，`CLAUDE_BIN` 路径是否存在

### 12.4 数据看板都是 0

按顺序检查：

1. 设置页是否通过微信公众号连接测试
2. 是否点击过“更新数据”
3. 公众号后台 IP 白名单是否配置正确
4. 数据同步结果里是否有未匹配或歧义标题
5. 文章是否已经发布到当前配置的公众号

## 13. 更新代码

以后拿最新代码：

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform
git pull origin master
```

如果前端依赖有变化：

```powershell
cd frontend
npm install
```

如果后端依赖有变化：

```powershell
cd backend
.\.venv\Scripts\activate
pip install -r requirements.txt
```

## 14. 不要提交这些本地文件

这些文件只属于自己的电脑，不要提交到 GitHub：

- `backend\.env`
- `backend\data\gzh_platform.db`
- `backend\scripts\wechat_stats_sync.log`
- 浏览器登录态、截图、临时抓取 HTML

项目 `.gitignore` 已经默认忽略这些文件。
