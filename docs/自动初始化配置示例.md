# 自动初始化配置示例

这份文档给第一次部署的同事使用。现在项目根目录已经内置 `.\start-dev.ps1`，推荐先用它启动：

```powershell
.\start-dev.ps1
```

脚本会自动创建 Python 虚拟环境、安装后端依赖、安装前端依赖并启动服务。进入设置页后，再点击“首次部署向导”创建内容目录并写入 `.env`。

下面的示例保留给需要自定义目录或了解初始化细节的用户。目标是用一段 PowerShell 脚本自动完成这些事情：

- 创建本地文章目录、爆款参考目录和数据目录
- 创建 Python 虚拟环境并安装后端依赖
- 安装前端依赖
- 生成 `backend\.env`
- 写入可迁移的默认目录配置和 AI Provider 示例

脚本不会替你填写真实的公众号密钥或 AI Key。运行后仍然需要打开设置页填写自己的账号信息。

## 使用前准备

先安装这些基础工具：

- Git
- Python 3.10+
- Node.js 20+
- npm

检查命令：

```powershell
git --version
python --version
node --version
npm --version
```

## 一键初始化脚本

在 PowerShell 中进入项目根目录后运行：

```powershell
cd C:\Users\你的用户名\Documents\gzh-platform
```

复制下面整段脚本执行：

```powershell
$ErrorActionPreference = "Stop"

$ProjectRoot = (Get-Location).Path
$Backend = Join-Path $ProjectRoot "backend"
$Frontend = Join-Path $ProjectRoot "frontend"
$ContentRoot = "C:\gzh-content"
$ArticlesDir = Join-Path $ContentRoot "articles\published"
$BenchmarksDir = Join-Path $ContentRoot "benchmarks"
$EnvFile = Join-Path $Backend ".env"
$PythonExe = Join-Path $Backend ".venv\Scripts\python.exe"

Write-Host "Project root: $ProjectRoot"

New-Item -ItemType Directory -Force -Path $ArticlesDir | Out-Null
New-Item -ItemType Directory -Force -Path $BenchmarksDir | Out-Null
New-Item -ItemType Directory -Force -Path (Join-Path $Backend "data") | Out-Null

if (-not (Test-Path $PythonExe)) {
  python -m venv (Join-Path $Backend ".venv")
}

& $PythonExe -m pip install --upgrade pip
& $PythonExe -m pip install -r (Join-Path $Backend "requirements.txt")

Push-Location $Frontend
npm install
Pop-Location

@"
GZHPUBLISHER_ROOT=$($ContentRoot.Replace('\', '/'))
ARTICLES_DIR=$($ArticlesDir.Replace('\', '/'))
BENCHMARKS_DIR=$($BenchmarksDir.Replace('\', '/'))

WECHAT_APP_ID=
WECHAT_APP_SECRET=
WECHAT_STATS_DAYS_BACK=365
WECHAT_STATS_MAX_WORKERS=1

AI_PROVIDER=openai_compatible
CLAUDE_BIN=
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=
AI_MODEL=deepseek-chat

HTTPS_PROXY=

FLASK_PORT=5001
FLASK_DEBUG=false
"@ | Set-Content -Path $EnvFile -Encoding UTF8

Write-Host ""
Write-Host "初始化完成。下一步："
Write-Host "1. 打开 backend\.env，填写 WECHAT_APP_ID / WECHAT_APP_SECRET / AI_API_KEY。"
Write-Host "2. 把本机公网 IP 加入微信公众号后台 IP 白名单。"
Write-Host "3. 运行 .\start-dev.ps1 启动系统。"
Write-Host "4. 打开 http://127.0.0.1:3001/settings 做环境检查。"
```

## 必须手动填写的值

运行脚本后，打开：

```powershell
notepad backend\.env
```

填写这些值：

```env
WECHAT_APP_ID=你的公众号 AppID
WECHAT_APP_SECRET=你的公众号 AppSecret
AI_API_KEY=你的 AI 服务 API Key
```

如果不使用 DeepSeek，把 AI 配置改成自己的服务商：

```env
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://你的服务商地址/v1
AI_API_KEY=你的 API Key
AI_MODEL=你的模型名
```

如果使用 Claude CLI，则改成：

```env
AI_PROVIDER=claude_cli
CLAUDE_BIN=C:/Users/你的用户名/AppData/Roaming/npm/claude.cmd
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
```

## 可选：安装排版发布依赖

如果只使用数据看板和文章生成，可以先跳过这一步。

如果要把文章排版并发布到微信公众号草稿，安装 Wenyan 相关依赖：

```powershell
npm install -g @wenyan-md/mcp @wenyan-md/core
```

安装后打开设置页，检查“Wenyan 排版依赖”是否通过。

## 启动系统

项目根目录运行：

```powershell
.\start-dev.ps1
```

然后打开：

```text
http://127.0.0.1:3001/settings
```

在设置页完成：

- 部署环境检查
- 测试微信公众号连接
- 测试 AI 连接

两个连接测试通过后，再去数据看板或发布中心使用。

## 数据看板定时同步

初始化脚本只负责配置本地环境，不会自动创建 Windows 定时任务。

如果要自动更新数据看板，可以在 Windows “任务计划程序”中新建任务，定时运行：

```text
backend\scripts\run_wechat_stats_sync.bat
```

建议频率：

- 普通使用：每天 09:00 和 18:00 各同步一次
- 发文频繁：每 2-4 小时同步一次

同步结果会写入本地 SQLite 数据库，看板会显示最近同步状态。

## 常见调整

如果你不想把文章目录放在 `C:\gzh-content`，修改脚本里的这一行：

```powershell
$ContentRoot = "C:\gzh-content"
```

例如：

```powershell
$ContentRoot = "D:\workspace\gzh-content"
```

如果公司网络需要代理，在 `backend\.env` 中填写：

```env
HTTPS_PROXY=http://127.0.0.1:7890
```

如果 Python 或 npm 安装依赖很慢，可以先配置公司推荐的镜像源，再重新运行脚本。

## 不要提交本地配置

这些文件只属于自己的电脑，不要提交到 GitHub：

- `backend\.env`
- `backend\data\gzh_platform.db`
- `backend\scripts\wechat_stats_sync.log`
- 本地浏览器登录态和抓取文件

项目已经通过 `.gitignore` 忽略它们。
